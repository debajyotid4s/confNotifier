  BD CONFERENCE BOT — PROJECT DOCUMENTATION
================================================================================

1. OVERVIEW
--------------------------------------------------------------------------------
An automated system that detects newly announced international conferences to
be held in Bangladesh and notifies subscribers via a Telegram channel. Runs
entirely on free infrastructure with zero manual intervention.

  Detection:   crt.sh cert transparency + university homepage scanning +
               special source monitoring (ICCIT, QPAIN, etc.)
  Extraction:  Google AI Studio — Gemini 2.5 Flash (single model, rate-limited)
  Database:    PostgreSQL on Neon (free tier)
  Scheduling:  GitHub Actions (cron every 6 hours)
  Delivery:    Telegram public channel
  Bot:         Koyeb (always-on free) — /start, /list, /subscribe

3. FILE DESCRIPTIONS
--------------------------------------------------------------------------------

config/universities.json
  - JSON array of Bangladeshi university domains (e.g. sust.edu, buet.ac.bd)
  - Used by crt_monitor.py and homepage_links.py

config/special_sources.json
  - Structured JSON array with type-based source definitions
  - Types: "path" (ICCIT-style /YYYY/home/ probing), "root_year" (QPAIN-style
    year extraction from page content)
  - Current sources: ICCIT, QPAIN, BECITHCON, SPICSCON, PEEIACON, ICECE, ICCHE

db/schema.sql
  - 3 tables: known_subdomains, seen_links, conferences
  - conferences: extracted column tracks LLM extraction status
  - No subscribers table (delivery is channel-based)

scraper/browser.py
  - Selenium Chrome driver factory with anti-bot measures:
    - --headless=new, --no-sandbox, --disable-blink-features
    - Rotating user agents (3 Chrome versions)
    - navigator.webdriver set to undefined via CDP
    - set_page_load_timeout(20), set_script_timeout(10)
  - human_delay(): random 1.5-4.0s pause
  - slow_scroll(): scroll page in 4-8 random steps
  - random_mouse_movement(): micro mouse movements via ActionChains
  - load_page(): loads URL with retry logic (1 retry, 5s wait)
  - BrowserManager: context manager for safe driver lifecycle

scraper/sources/crt_monitor.py
  - 3 broad crt.sh queries: %.ac.bd, %.edu.bd, %.edu, %.sust.edu
  - Filters results by conference-like subdomain patterns
  - SUBDOMAIN_BLOCKLIST blocks known non-conference prefixes (includes ict.)
  - For %.edu results, filters by exact BD university domain matching
  - 3-phase DB access: load known -> query crt.sh -> save new (no long-held conn)
  - Returns list of https:// URLs

scraper/sources/homepage_links.py
  - Uses requests + BeautifulSoup (no Selenium) to fetch each homepage
  - fetch_homepage_fast(): multi-strategy (requests -> curl -> Selenium fallback)
  - CURL_ONLY_DOMAINS for sites with broken HTTP headers (buet.ac.bd)
  - SSRF protection: _is_safe_url() blocks private IPs, localhost, dangerous schemes
  - Extracts outbound <a href> links via BS4
  - Uses _save_link() — fresh DB connection per save, closed immediately
  - Returns list of new candidate URLs

scraper/sources/special.py
  - Multi-type source handler based on "type" field in special_sources.json
  - "path" type: probes /YYYY/home/ then /YYYY/ for each year
  - "root_year" type: fetches base URL, extracts year from <title>/<h1>/text
  - SSRF protection: _is_safe_url() before any fetch
  - All DB operations use fresh-per-operation connections
  - Returns flat list of candidate URL strings

scraper/extractor.py
  - DNS pre-check (_is_url_reachable()) before Selenium
  - GoogleRateLimiter: 15 RPM, 1500 RPD (rolling window, thread-safe)
  - Gemini 2.5 Flash via Google AI Studio OpenAI-compatible API
  - max_retries=0 on OpenAI client (we handle 429s ourselves)
  - Fetches page text via Selenium + BeautifulSoup (first 8000 chars)
  - Returns parsed dict or None if extraction fails

scraper/deduplicator.py
  - Checks conferences table for duplicates by website URL
  - Opens/closes its own DB connection per call
  - Returns True if duplicate found

scraper/notifier.py
  - Formats conference data into emoji-rich Telegram message
  - Generates PascalCase hashtags from title, category, city
  - Posts to TELEGRAM_CHANNEL_ID or TELEGRAM_CHANNEL_LINK via bot API
  - Auto-converts https://t.me/name -> @name for API compatibility
  - Returns True/False on success/failure
  - No hardcoded credentials — requires env vars

scraper/main.py
  - Orchestrator that runs all phases:
    Phase 1: crt_monitor.run()    (isolated try/except)
    Phase 2: homepage_links.run() (isolated try/except)
    Phase 3: special.run()        (isolated try/except)
    Phase 4: Extract + deduplicate + save + notify loop
    Phase 5: _notify_pending() — catch-all for unnotified conferences
  - Validates required env vars at startup (DATABASE_URL, GOOGLE_AI_KEY,
    TELEGRAM_BOT_TOKEN, TELEGRAM_CHANNEL_ID/TELEGRAM_CHANNEL_LINK)
  - Skips conferences where date_start < today (both in Phase 4 and _notify_pending)
  - _notify_pending(): cleans up past conferences, retries failed notifications
  - All DB connections are fresh-per-operation (no long-held connections)
  - Orphaned URL reprocessing: URLs in seen_links without conference entry
  - Prints summary: X found, Y new, Z skipped, W failed

bot/bot.py
  - Telegram bot with 3 commands:
    /start     — welcome message with channel link
    /list      — queries upcoming conferences (LIMIT 10)
    /subscribe — sends channel join link
  - Health check endpoint (GET /health -> "ok") on port 8081 in daemon thread
  - Runs in webhook mode on port 8080 (Koyeb deployment)
  - Connects to same Neon PostgreSQL

.github/workflows/scraper.yml
  - Trigger: cron "0 */6 * * *" + workflow_dispatch
  - Steps: install Chrome -> setup Python 3.11 -> pip install -> run scraper
  - Passes 5 secrets: DATABASE_URL, GOOGLE_AI_KEY, TELEGRAM_BOT_TOKEN,
    TELEGRAM_CHANNEL_ID, TELEGRAM_CHANNEL_LINK
  - Sets PYTHONPATH=. for scraper imports


4. DATA FLOW (End to End)
--------------------------------------------------------------------------------
  crt.sh query (3 broad TLD queries)
       |
       v  New subdomain like icXXXX.university.ac.bd found
       |
  homepage_links (requests + BS4 scans all university homepages)
       |
       v  Outbound conf link found on a homepage
       |
  special.py (probes ICCIT /YYYY/home/, QPAIN year detection, etc.)
       |
       v  New annual edition detected
       |
  All candidates combined, deduplicated by URL set
       + orphaned URLs from previous failed runs
       + unextracted URLs from quota exhaustion
       |
       v
  extractor.py — DNS check -> Selenium load -> Gemini 2.5 Flash extraction
       |           (rate-limited: 15 RPM, 1500 RPD)
       v  LLM returns structured JSON or null
       |
  Dedup check -> date filter (skip past conferences) -> save to conferences
       |
       v
  notifier.py — format + POST to Telegram channel
       |
       v
  _notify_pending() — catch any unnotified conferences (cleanup + retry)
       |
       v  All channel subscribers see notification

6. KNOWN ISSUES & TECHNICAL DEBT
--------------------------------------------------------------------------------

  a) extractor.py spawns a new Chrome instance per candidate URL
     - Inefficient for many candidates; BrowserManager should be reused

  b) No shared db utility module
     - DB connection code (3-retry pattern) duplicated across files

  c) bot.py CHANNEL_LINK not configurable via env var
     - Changing channel requires code deploy

  d) Health check on separate port (8081) not probed by Koyeb by default
     - HEALTH_CHECK_PORT must be set to match PORT

  e) Gemini 2.5 Flash 15 RPM limit is tight
     - 3 candidates/min with 3 retry attempts each can exhaust quota quickly
     - max_retries=0 helps but rate limiter still needs tuning

  f) Special sources with unpredictable URL patterns cannot be auto-detected
     - RAAICON uses date-based paths that change yearly


7. INFRASTRUCTURE & SETUP
--------------------------------------------------------------------------------

  GitHub Secrets (required):
    DATABASE_URL          — Neon PostgreSQL connection string
    GOOGLE_AI_KEY         — From aistudio.google.com (free tier)
    TELEGRAM_BOT_TOKEN    — From @BotFather
    TELEGRAM_CHANNEL_ID   — Channel ID (e.g. @BDConferences) OR
    TELEGRAM_CHANNEL_LINK — Channel link (e.g. https://t.me/BDConferences)

  One-time setup:
    1. Create GitHub repo and push code
    2. Sign up at neon.tech -> create project -> get DATABASE_URL
    3. Run db/schema.sql on Neon to create tables
    4. Sign up at aistudio.google.com -> get GOOGLE_AI_KEY
    5. Create bot via @BotFather -> get TELEGRAM_BOT_TOKEN
    6. Create public Telegram channel -> add bot as admin
    7. Add 4+ secrets to GitHub repo (Settings -> Secrets -> Actions)
    8. Deploy bot/bot.py on Koyeb with same env vars
    9. Trigger first run manually via GitHub Actions -> workflow_dispatch
   10. Confirm first run completes without errors in Actions log


8. LLM CONFIGURATION (Google AI Studio — Gemini 2.5 Flash)
--------------------------------------------------------------------------------
  Model: gemini-2.5-flash (via Google AI Studio OpenAI-compatible API)
  Rate limits:
    - 15 requests/minute (rolling window)
    - 1500 requests/day (resets at midnight Pacific)
    - 1M tokens/minute
  Fallback: single model, no fallback chain
  Rate limiter: GoogleRateLimiter class (thread-safe, blocks until slot available)
  OpenAI client: max_retries=0 (we handle 429s ourselves)
